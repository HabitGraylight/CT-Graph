# 调酒建议工作台 · 第一版

## 启动与使用

在仓库根目录中执行（新克隆先运行 `python scripts/init_local.py`）：

```powershell
python server.py --port 8765
```

打开 http://127.0.0.1:8765 。仅监听本机，无需账号、API Key 或在线模型。

1. 选择框架。
2. 输入配方，每行一种或用逗号分隔，例如 `金酒 45ml，青柠汁 25ml，原味糖浆 20ml`。
3. 选择制作技法，点击“评价我的配方”。
4. 需要补全时，可以只写原料名；在“材料架”填写已有材料，点击“按框架帮我补全”。
5. 查看需添购材料、备选配料、制作步骤，采用草案或按份数缩放。
6. 保存到试饮手记，记录实际酸甜和下次调整。

“传统配方对照”展示多个来源的原料、品牌、用量、方法、杯型与装饰。“原料词典”支持中英文和品牌检索，可将材料加入库存。

浏览器草稿和试饮手记存于 localStorage，只在当前浏览器及该端口下可见，清理浏览器站点数据会清除记录；尚未接入账户或云同步。示例手记明确标注未实际试饮。

## 支持的 12 个框架

这些是便于创作的分类与规则，并非声称存在唯一的官方“十二大框架”。比例范围由本项目编辑定义，参考配方保留 IBA 来源。

| ID | 框架 | 核心结构 | 默认试配 |
|---|---|---|---|
| sour | 酸酒 | 基酒 + 酸 + 糖浆 | 45 / 25 / 20 ml |
| daisy | 橙酒酸酒 | 基酒 + 酸 + 橙酒 | 50 / 20 / 20 ml |
| old_fashioned | 古典 | 基酒 + 少量糖浆 + 苦精 | 45 / 5 ml + 2 dash |
| martini | 干马天尼 | 金酒或伏特加 + 干味美思 | 60 / 10 ml |
| manhattan | 曼哈顿 | 威士忌 + 甜红味美思 + 苦精 | 50 / 20 ml + 1 dash |
| negroni | 尼格罗尼 | 基酒 + 红色苦味开胃酒 + 甜红味美思 | 30 / 30 / 30 ml |
| highball | 高球 | 基酒 + 填充饮料 | 45 / 120 ml |
| collins | 柯林斯 / 菲士 | 基酒 + 酸 + 糖浆 + 苏打 | 45 / 25 / 15 / 60 ml |
| spritz | 斯普利兹 | 起泡葡萄酒 + 开胃酒 + 苏打 | 90 / 60 / 30 ml |

## 原料对齐范围

- 127 个常见原料类别及明确产品，保留中英文名、别名、角色、品牌和父类。
- 1,241 个原配方版本全部经过对齐管线，原始文件不改动。
- 5,770 行原料中，3,487 行成功匹配；社区自由文本与长尾品牌仍有未识别项。
- IBA 官方配方 413 行中，339 行已识别，约 82.1%。
- 122 组同名配方生成差异报告，其中 91 组有 IBA 官方版本可对照。
- 未识别、歧义、修复前缀和原始表达均留在 `data/aligned`，未将未识别材料抛弃后声称完成全部对齐。

中英文映射是人工整理的常用名称；某些中文品牌有地区译法，不视作唯一官方译名。品牌类别依据现有原料资料及厂商说明；相关链接见 `cocktail/knowledge.py`。角色分配属于本项目建议模型，不是源站授予的标准。

### 不混同的例子

- 君度与 Cointreau → 同一产品；该产品属于 Triple Sec 类，但不覆盖其他橙酒品牌。
- 百加得白朗姆 → 明确产品；仅“百加得”要求用户确认。
- 马天尼红 / 干 / 白甜味美思 → 分开；仅“马天尼”有歧义。
- 金巴利 / 阿佩罗、苏打 / 汤力、姜汁啤酒 / 干姜水 → 不合并。
- 杏仁糖浆 / 杏仁利口酒、原味糖浆 / 浓糖浆、蜂蜜 / 蜂蜜糖浆 → 不合并。
- 干邑 / 白兰地、白朗姆 / 深色朗姆 → 保留类型层级；不是凭模糊字符串匹配而合并。
- 甜椰浆 / 椰奶油 / 椰奶 → 分开。

配方差异分为新增原料、缺少原料、公制用量改变、同量换产品、单位或数量不可比、数量未指定、名称未解析。30 ml 与 3 cl 的等价公制用量不产生用量差异。品牌和品类级别变化仍会保留。

## 评分方法与限制

总分称为“框架契合度”，不是好喝程度、专家评分或真实试饮结果。

- 核心槽位完整度 40 分。
- 配比符合当前编辑定义范围的程度 40 分。
- 输入清晰度 10 分。
- 技法匹配 10 分；未选技法时用其余 90 分折算为百分制。

主要液体槽位相对基酒计算比例，因此整杯放大不改变比例分。超出范围时按偏离程度扣分，并显示哪里偏多、偏少。苦精 dash 与薄荷叶数按独立范围检查，不伪装成 ml。

若名称不明、有歧义、核心用量不可解释，或出现框架没有建模的附加主料，不输出总分。仍提供结构缺口和需要确认的信息。气泡材料摇和会提示改为后加入。

原味糖浆以常见 1:1 作为试配参照；浓糖浆的甜味贡献默认乘 1.5，只是近似启发式，不是含糖实测。蜜糖、龙舌兰糖浆、不同果汁的品牌/浓度差异尚未实验标定。没有自动估算 ABV、营养、过敏风险或真实味觉评分。

最近经典酒按原料类别交集排序；未知的源原料仍计入分母，避免因漏识别而夸大重合。该排序不等于味觉相似度或传统配方忠实度。

## 补全与推荐方法

优先保留你明确填入的量 → 为缺少用量的已识别材料给试配量 → 用现有材料填缺少的角色 → 列出仍需补充的材料。只匹配明确身份，不从“马天尼”猜红白或干型。

“糖浆少一点”仅对新补的糖浆减少 20%，不会改写你已填好的糖浆量。指定“补全时不使用”的原料及其明确品牌子类不会进入补全或备选清单；此约束不是过敏原过滤器。

备选材料按结构角色与库存排序，标注其非等味等量替换性质。原料架功能寻找核心原料齐全或只差一种的官方配方，不能证明瓶中余量足够。含未知核心原料的配方不进入“核心材料已齐”结果；必要的蛋清不会被自动忽略。

这是一版可解释、可离线运行的规则系统。页面支持简短配方文字和列表，不支持任意复杂自然语言的可靠语义理解。后续可在现有接口上接入模型，把用户语言转换为结构化输入，再交给这些规则和传统来源检查。

## 给助手或代码调用的入口

```powershell
python scripts/advise.py evaluate --frame sour --recipe "金酒 45ml，青柠汁 25ml，糖浆 20ml" --method shake
python scripts/advise.py complete --frame negroni --recipe "金酒 30ml" --pantry "金巴利、马天尼红"
python scripts/advise.py compare --name "尼格罗尼"
python scripts/advise.py pantry --pantry "金酒、君度、青柠汁"
```

Python 入口：`cocktail.engine.evaluate`、`complete`、`compare`、`pantry_matches`。输出 JSON 具有原料解析状态、解释、来源 URL、待补充项与评分维度。

HTTP：`GET /api/catalog`、`GET /api/compare?name=Negroni`，以及 `POST /api/evaluate`、`/api/complete`、`/api/pantry`。POST 参数与 CLI 对应，JSON 对象例子：

```json
{"frame":"negroni","recipe":"金酒 30ml","pantry":"金巴利、马天尼红","avoid":"","preference":"balanced"}
```

## 文件与维护

- `cocktail/knowledge.py`：词典、歧义名称、鸡尾酒别名、框架、参考来源及规则范围。
- `cocktail/normalization.py`：中英匹配、输入解析、单位处理。
- `cocktail/engine.py`：评分、补全、原料架匹配、来源比较。
- `scripts/align_data.py`：生成 `data/aligned/`，与旧 `data/processed/` 分层保存。
- `web/`：中文本地页面。
- `server.py`：标准库 HTTP 服务，仅监听 127.0.0.1。
- `tests/`：规则行为、出处、HTTP 接口测试。

修改知识定义后运行 `python scripts/align_data.py`，然后重启 `server.py`，刷新页面；数据和规则以进程级缓存加载。

```powershell
python scripts/align_data.py
python -m unittest discover -s tests -v
python scripts/validate.py
node --check web/app.js
```

本地研究原文的授权边界仍适用，详见 `DATA_NOTES.md`。本服务不公开发布到互联网，不暴露原始文件目录。
