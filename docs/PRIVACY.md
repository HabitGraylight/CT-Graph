# 发布边界与本地数据

CT-Graph 仓库只发布通用代码、人工编写的方法、文档、技能和合成测试。个人数据不进入提交，也不进入 Git 历史、Issue、PR、CI 日志或发布附件。

| 内容 | 位置 | GitHub |
|---|---|---|
| 引擎、调酒框架、双语词典、定性机制构建脚本 | cocktail/、scripts/ | 审核后按白名单发布 |
| 技能、结构设计、合成示例及测试 | .agents/、docs/、tests/、examples/ | 审核后按白名单发布 |
| 私人配方、材料架、酒单、偏好 | data/personal/ | 仅本地 |
| 实际试饮与待审知识笔记 | data/feedback/ | 仅本地 |
| 请求、候选、临时输出 | data/work/、tmp/ | 仅本地 |
| 菜单、PDF、图片、出杯方案等生成物 | output/ | 仅本地 |
| 采集原文与派生数据 | data/raw/、data/processed/、data/aligned/ | 仅本地，不随代码再分发 |
| 实际启用的知识版本及审核历史 | data/knowledge/ | 仅本地；公共默认规则由构建脚本产生 |
| 浏览器草案和手记 | localhost 的 localStorage | 仅该浏览器，不随 Git 同步 |

## 发布流程

`public-files.json` 是逐文件白名单；`.gitignore` 默认忽略未列出的文件。新增文件先判断是否可复用，清除个人实例后再显式加入白名单；不要通过复制真实酒单来构造测试。

1. 查看将发布的文件内容与差异，尤其文档、示例、测试和公共规则。
2. 使用 `git add` 添加经过审核的具体文件。
3. 运行 `python scripts/check_publication.py`，核对暂存区文件、历史路径和常见凭据模式。
4. 查看 `git diff --cached` 后再提交；推送前再次运行检查。

检查器不能识别写进允许文件中的所有个人信息，人工复核仍然必要。`.gitignore` 不会取消已跟踪文件，也不会清除历史。不要用 `git add -f` 绕过边界。若发现历史含有私密内容，先停止发布并单独处理；不要擅自强推历史。

新克隆运行 `python scripts/init_local.py` 创建本地目录和默认知识，不联网、不填充真实反馈、不覆盖已有文件。个人备份需单独安排；GitHub 代码仓库不是个人数据备份。

来源版权与代码许可分别处理：仓库不附采集网页及完整配方语料；采集和使用须遵循原来源条款。当前未指定代码开源许可证，公开仓库本身不等于授予任意再分发许可。
